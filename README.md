# ACT — секции рядом с домом

Чат-бот в MAX + сайт записи, которые помогают родителю подобрать спортивную
или творческую секцию для ребёнка и записать его в пару шагов.

Бот в MAX сначала уточняет район и возраст ребёнка, а затем проводит
профориентационный тест из 8 вопросов (по одному варианту ответа, без
"правильных" — каждый вариант отдаёт балл одному из 5 направлений: футбол,
дзюдо, плавание, рисование, театр). По направлению с максимумом баллов бот
подбирает подходящие секции и присылает кнопку с прямой ссылкой на сайт ACT,
уже предзаполненной результатом теста (если несколько направлений набрали
поровну — бот показывает все их сразу, без дополнительных вопросов). На
сайте родитель может уточнить выбор через фильтр, открыть карточку секции
и отправить заявку — письмо с заявкой реально уходит на почту организатора
через EmailJS.

Логика самого теста (вопросы, варианты ответов, подсчёт баллов) — в
[`backend/internal/dialog/quiz.go`](backend/internal/dialog/quiz.go).

## Архитектура

```
Родитель в MAX
      │
      ▼
backend (Go)  ──long polling──>  MAX Bot API
      │
      ▼
mock-api (json-server) ──справочник секций──┐
      │                                      │
      ▼                                      ▼
ссылка на сайт с параметрами        web-app (статика + nginx)
type / age / district                читает тот же mock-api
```

- **backend** — Go-бот: диалоговый автомат (`internal/dialog`), клиент MAX Bot
  API поверх [maxigo-client](https://github.com/maxigo-bot/maxigo-client)
  (`internal/clients/maxapi`), клиент справочника секций
  (`internal/clients/mockapi`), доменные модели и контракт хранилища заявок
  (`internal/domain`, `internal/storage` — в MVP заявки создаются на сайте, а
  не ботом, поэтому репозиторий пока подключён, но не используется).
- **mock-api** — [json-server](https://github.com/typicode/json-server) поверх
  `mock-api/db.json`: единый источник данных о секциях для бота и сайта.
- **web-app** — статический сайт записи (без своего бэкенда), подробности и
  настройка EmailJS — в [`web-app/README.md`](web-app/README.md).

## Быстрый старт (Docker)

Нужны `docker` и `docker compose`.

```bash
make init      # создаёт .env из .env.example
# откройте .env и заполните MAX_BOT_TOKEN (и остальные переменные ниже)
make env-up    # поднимает все три сервиса
make env-diag  # проверка, что mock-api жив и отдаёт данные
```

Для показа на реальном телефоне (а не только в браузере на той же машине)
важно правильно заполнить `WEB_APP_URL` в `.env` — иначе кнопка результата
теста в боте не откроется. Подробности и варианты (LAN-адрес, туннель) — в
комментарии над `WEB_APP_URL` в `.env.example`.

`make help` печатает список всех команд с описанием (запуск, пересборка,
логи, локальный запуск бэкенда вне Docker и т.д.).

## Переменные окружения (`.env`)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `PROJECT_NAME` | да | префикс имён контейнеров |
| `BACKEND_PORT` | да | порт бэкенда на хосте |
| `MOCK_API_PORT` | да | порт mock-api на хосте |
| `WEB_APP_PORT` | да | порт сайта на хосте |
| `MAX_BOT_TOKEN` | да | токен бота из MAX |
| `MAX_BOT_USERNAME` | нет | username бота (для кнопок открытия мини-приложения, если понадобятся) |
| `WEB_APP_URL` | нет | адрес сайта ACT, который бот подставляет в кнопку результатов. Для локального Docker по умолчанию `http://localhost:<WEB_APP_PORT>`; **для демонстрации на реальном телефоне нужен публично доступный адрес** (домен или туннель), иначе кнопка не откроется |

Остальные переменные бэкенда (`LOG_LEVEL`, `LOG_FORMAT`, `MAX_API_BASE_URL`,
`STORAGE_KIND`) имеют рабочие значения по умолчанию — см.
`backend/internal/config/config.go`; в `docker-compose.yml` не
прокинуты, но подхватываются при локальном запуске (`make backend-run`).

## Структура репозитория

```
backend/     Go-бот (см. выше)
mock-api/    json-server + db.json — справочник секций
web-app/     сайт записи (см. web-app/README.md)
docker-compose.yml, Makefile, .env.example — инфраструктура
```

## Известные ограничения MVP

- Хранилище заявок и очереди ожидания — только в памяти процесса бэкенда
  (`internal/storage`), данные теряются при перезапуске контейнера.
- Шаг записи через Госуслуги на сайте — демо (таймер), помечен в интерфейсе
  как точка будущей интеграции; см. `web-app/README.md`.
- Сайт открывается по обычной ссылке из бота, а не как MAX-мини-приложение
  (`open_app`) — это заложено как направление масштабирования.
- Все данные — по Владимиру; район сейчас выбирается один раз (в боте) и
  автоматически передаётся на сайт через параметр `district`.
